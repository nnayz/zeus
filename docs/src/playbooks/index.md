# Playbooks

Playbooks are the short paths through Taskmaster for a job you already know you
want to do. Each one says when it applies, what you need, the steps, what
you should see, and the mistakes that waste a session.

Reference pages still own the full shortcut lists and settings. Start here
when you want the workflow.

| Playbook | Use it when |
|----------|-------------|
| [Parallel agents in worktrees](parallel-worktrees.md) | More than one agent will edit the same repository |
| [Delegate and follow child sessions](delegate.md) | A lead should hire other sessions and you want to follow them |
| [Review changes and open a pull request](review-pull-request.md) | You need to read a diff and get to the pull request |
| [Local or remote, and reconnect](local-or-remote.md) | The agent should run here or on another machine, and you need it again later |
| [A session is waiting](needs-input.md) | A row stopped and you are not sure why |
| [Idle sessions and resource limits](idle-and-limits.md) | The fleet is large, or you are leaving it running |

[Fleet patterns](../fleet.md) is the broader catalog of ways to mix these.
Playbooks stay on behavior Taskmaster already ships.
